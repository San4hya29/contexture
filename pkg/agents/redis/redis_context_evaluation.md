# Redis Context Evaluation

## 🎯 Objective
This evaluation demonstrates the impact of introducing **Redis Context** into the AI execution pipeline. The same natural language queries were executed under two different configurations:

1. **Without Redis Context** – The LLM only receives the discovered Redis schema and raw tools.
2. **With Redis Context** – The LLM additionally receives enriched Redis context generated by the background context collector, including entity relationships, semantic keyspace definitions, and operational constraints/business rules.

The comparison illustrates how this contextual information drastically improves answer accuracy and enables correct command/tool selection.

## 🧠 Redis Context Used for Evaluation
When **Redis Context** is enabled, the Redis Context Collector generates a semantic description of the Redis dataset and supplies it to the LLM before query execution. This context complements the discovered Redis schema by describing the business meaning of keys, their relationships, and domain-specific rules.

The generated context contains three major components:
*   **Entities** – High-level business objects represented in Redis.
*   **Key Semantics** – Descriptions of Redis key patterns and the data structures they map to.
*   **Business Rules** – Domain-specific constraints that guide the LLM reasoning.

### 📋 Sample Context Structure

#### Entities
*   **User**: Shopper accounts stored in Redis.
*   **Cart**: Products currently selected for purchase.
*   **Wishlist**: Products saved for later.
*   **Product**: Cached product metadata stored as JSON.
*   **Purchase**: Purchase transaction records.
*   **Order**: Pending purchase orders awaiting processing.

#### Key Semantics

| Key Pattern | Data Type | Description |
| :--- | :--- | :--- |
| `user:*` | Hash | Stores user information such as name, email, age, and status. |
| `cart:user:*` | Set | Contains products currently added to a user's cart. |
| `wishlist:user:*` | Set | Contains products saved for later by a user. |
| `cache:product:*` | String (JSON) | Stores cached product metadata (name, price, etc.) as JSON. |
| `high_score_buyers` | Sorted Set (zset) | Sorted set ranking users by total purchase value. |
| `purchase_stream` | Stream | Stream containing purchase transactions. |
| `order_queue` | List | Queue containing pending order IDs. |

#### Business Rules
*   Only active users may checkout.
*   Orders are immutable after creation.
*   Cache keys have custom TTL bounds (e.g., 1800–3600 seconds).

## 📊 Evaluation Results

### 1. 🛑 Without Redis Context

> [!WARNING]
> Without semantic descriptions, the LLM often struggles to map relationship links between keys, falls back to raw listing outputs, or fails to fetch dynamic values within key objects.

*   **Query**:
    ```bash
    python -m app.cli "What is the email of user Bob Jones?"
    ```
    **Output**:
    > The provided tool result only lists Redis keys (`user:1`, `user:2`) and does not contain any user data such as emails. To retrieve Bob Jones' email, you would need to check the values stored in these keys (e.g., using `GET user:1` or `GET user:2`). The current result does not provide sufficient information to answer the question.

*   **Query**:
    ```bash
    python -m app.cli "Which products appear in both cart and wishlist?"
    ```
    **Output**:
    > No products appear in both the cart and wishlist based on the provided data. The cart contains items for user 1 (`cart:user:1`), while the wishlist contains items for user 2 (`wishlist:user:2`). There is no overlap in the keys or users referenced.

*   **Query**:
    ```bash
    python -m app.cli "Which user has made the highest purchase?"
    ```
    **Output**:
    > The user with the highest purchase is **user:1**, who has made a total purchase of **$1,500.00**. This result is derived from the sorted set `high_score_buyers`, where user:1 holds the highest score.

*   **Query**:
    ```bash
    python -m app.cli "What is the price of product 102"
    ```
    **Output**:
    > The price of product 102 is **$29.99**. This information was retrieved from the Redis key `cache:product:102`, which stores product details in a JSON format.

*   **Query**:
    ```bash
    python -m app.cli "What are the cart items of user 1"
    ```
    **Output**:
    > The cart items for user 1 are stored in the Redis set `cart:user:1` and contain the following product keys:
    > *   `cache:product:101`
    > *   `cache:product:102`
    > 
    > These keys reference cached product entries. To retrieve detailed information about these products, you would need to query the `cache:product:*` keys directly.

### 2. 🟢 With Redis Context

> [!NOTE]
> Enriched context allows the planner to understand nested formats (such as JSON strings inside string keys), use correct structural instructions (e.g. `hgetall` for user hashes), and correctly cross-reference sets between users.

*   **Query**:
    ```bash
    python -m app.cli "What is the email of user Bob Jones?"
    ```
    **Output**:
    > The email of user Bob Jones is **bob@example.com**. This information was retrieved from the Redis hash key `user:2` using the `hgetall` command.

*   **Query**:
    ```bash
    python -m app.cli "Which products appear in both cart and wishlist?"
    ```
    **Output**:
    > The product that appears in both the cart and wishlist is **product 101**. This was determined by performing an intersection (`SINTER`) between the sets `cart:user:1` and `wishlist:user:2`, which yielded the key `cache:product:101`.

*   **Query**:
    ```bash
    python -m app.cli "Which user has made the highest purchase?"
    ```
    **Output**:
    > The user with the highest purchase is **user:1**, as indicated by the `high_score_buyers` zset, where they have a purchase score of **1500.0** (the highest value in the sorted set).

*   **Query**:
    ```bash
    python -m app.cli "What is the price of product 102"
    ```
    **Output**:
    > The price of product 102 (Wireless Mouse) is **$29.99**.

*   **Query**:
    ```bash
    python -m app.cli "What are the cart items of user 1"
    ```
    **Output**:
    > The cart items for user 1 are products with IDs **101** and **102**, as indicated by the Redis keys `cache:product:101` and `cache:product:102`.
